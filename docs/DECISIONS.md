# Решения (DECISIONS)

Короткий журнал решений, принятых по ходу работы, и причины.

## Этап 1. Эталон AFL++
- **Папка проекта** — `neat-fuzzer` (в задании упомянута `neuroevo-fuzz`, но рабочая папка репозитория называется так; содержимое было пустым — только пустые каталоги, они удалены).
- **Имя папки запуска**: `YYYY-MM-DD_HH-MM-SS_<вид>` (секунды добавлены, чтобы два запуска в одну минуту не столкнулись; суффикс `_afl`/`_neat`/`_compare` показывает тип запуска).
- **AFL++ пишет очередь в `/tmp` контейнера**, а не в примонтированную папку Windows: bind-mount Docker Desktop медленный и не допускает `:` в именах файлов. Нужное копируется в `results/` после завершения.
- **Метрика покрытия = число различных рёбер (edge id) по `afl-showmap`.** Для AFL++ после фаззинга вся очередь прогоняется через `afl-showmap` (`docker/afl_replay.py`) и строится кривая по времени появления файлов очереди. Нейрофаззер считает рёбра тем же `afl-showmap` на том же бинарнике — метрики сравнимы. Внутренний счётчик `edges_found` AFL сохранён в колонке `edges_afl` для справки (`plot_data` пишется AFL только раз в ~60 с в начале, поэтому как основная кривая не годится).
- **Уникальные краши AFL** = файлы в `crashes/` (AFL сам дедуплицирует по новизне пути).
- **Мини-таргеты** (`targets/mini/*.c`) собираются без ASAN: баги сделаны детерминированными (abort, SIGFPE, NULL, переполнение стека), а ASAN заметно замедляет запуск процесса.

## Этап 2. Таргеты (Magma / libpng)
- **libpng из Magma собран** (`docker/build_libpng.sh`, ~16 с): коммит libpng `a37d483`, патчи Magma setup + PNG001..PNG007, харнесс `contrib/oss-fuzz/libpng_read_fuzzer.cc` + `libAFLDriver.a`. Полный фреймворк Magma (captain, свои Docker-образы) не используется — только его патчи: так проще и быстрее, бинарник встаёт в общий реестр `TARGETS`.
- **Без канареек Magma, с ASAN.** Канарейки требуют общего хранилища `canaries.raw` и монитора; для нашего сравнения достаточно факта краша. Баги Magma без ASAN обычно не роняют процесс, поэтому собираем с `AFL_USE_ASAN=1`.
- **В образе нет утилиты `patch`** → патчи применяются `git apply --unidiff-zero` (в setup-патче ханки без контекста); CRLF из Windows-клона убираются `tr -d '\r'`.
- **ASAN + WSL2:** clang 16 ASAN случайно падает при старте (SIGSEGV до чтения входа, ~30% запусков) на ядре 6.18 с `vm.mmap_rnd_bits=32`. Решение: запуск под `setarch x86_64 -R` (без ASLR) и контейнеры с `--security-opt seccomp=unconfined` (иначе `personality()` запрещён). Проверено: 6/20 сбоев → 0/20.
- Проверка: AFL++ 90 с на libpng — 921 ребро, ~2.5 млн исполнений, 0 крашей (ожидаемо: баги Magma находятся за часы, а не минуты). Поэтому для коротких сравнений основной таргет — мини-таргеты, libpng — для покрытия.

## Этап 3. Исполнитель
- **Долгоживущий контейнер вместо `docker run` на каждый вход.** `docker run` стоит ~1 с; сервер `docker/executor_server.py` запускается один раз и принимает пачки входов по stdin/stdout (бинарный протокол). Входы пишутся на tmpfs `/fz` (в `/dev/shm` afl-showmap писать отказался).
- **Пачка = один вызов `afl-showmap -Z -i dir`** (forkserver, без fork+exec самого showmap на каждый вход): ~1800 исп./с на мини-таргетах и libpng при пачке 100–200. Флаг `-Z` (режим afl-cmin) не пишет карту для крашей и таймаутов (файл отсутствует или пуст) — такие входы перезапускаются поштучно, код возврата afl-showmap даёт статус (0/1/2 = ok/таймаут/краш). Нормальный запуск всегда даёт ≥1 ребро, поэтому пустая карта = «подозрение на краш».
- **Уникальность краша** как в AFL: краш уникален, если его путь содержит ребро, не встречавшееся в путях прошлых крашей (по edge id, без учёта счётчиков).
- **Корпус** пополняется входом, если он дал новую пару (ребро, класс счётчика) — аналог «new bits» AFL.
- **Мини-таргеты собираются с `-O0` и `AFL_DONT_OPTIMIZE=1`** (afl-cc по умолчанию сам добавляет `-O3`). Замечание: PCGUARD не инструментирует блоки цепочки с одним входом/выходом, поэтому на одном входе число рёбер почти не растёт с глубиной магии, но каждое место выхода — своё ребро, и объединение рёбер по корпусу растёт.
- **`mutations.py`** — общий набор из 8 операторов (bitflip, set_byte, insert, delete, interesting, arith, clone_block, splice). `havoc` = случайная стопка операторов — используется в самопроверке и как третий участник сравнения («случайный» фаззер), чтобы отделить вклад нейросети от вклада самих операторов.
